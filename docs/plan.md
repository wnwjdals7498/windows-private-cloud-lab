# Windows 사설 클라우드 실습 계획

> **2026-10-02: 실행 순서는 [기능·의존성·구현 순서 상세 계획](implementation-plan.md)을 참조한다.** 아래는 구조 재검토 이전의 초안이다. PHP 직접 연동·보안·클러스터 시점 등은 최신 PMT 결정과 다를 수 있어 그대로 실행하지 않는다. 기존 작성 내용은 이력으로 보존한다.

> 전체 구조 재검토 중. 현재 배치·단계는 [구조 재검토 기준표](../../docs/projects/architecture-review.md)의 확인을 거쳐 갱신한다.

> 최신 사용자 규모: AD·DNS VM 1대 + VMM·SQL VM 1대 + Compute 3대 + Storage 3대의 **8대**로 클러스터를 검증한다. 추가 각 2대를 종료·자동 부팅 제한하고 서비스 확인에는 관리 2·Compute 1·Storage 1의 **4대**만 가동한다. Linux 8대와 동시 시험하지 않는다. 아래의 기존 순서는 재작성 전 초안이다.

## 목표

단일 물리 Windows 11 Pro Hyper-V 호스트에 Windows Server 2022 컴퓨트 노드 VM을 만들고 중첩 Hyper-V를 설치한다. 컴퓨트 노드에서 VM 생성·삭제를 시험한 뒤 VMM용 VM을 만들고 노드를 편입하며 관리포털과 연결한다. 클러스터·DPM은 환경 확보 후 검토한다.

운영자 화면의 방향은 [UI 가이드](ui/guide.md)와 [HTML 목업](ui/mockup.html)에서 먼저 검토한다.
실제 호스트·VM 실습 화면은 별도 웹앱으로 만들지 않고 PHP·CodeIgniter 관리포털의 관리자 메뉴에 통합한다.

포털 신청부터 첫 Rocky Linux VM 부팅까지의 공동 최소 범위는 [cloud-management-portal-lab의 첫 동작 결과 계획](https://github.com/wnwjdals7498/cloud-management-portal-lab/blob/main/docs/first-working-slice.md)에 정리한다.

## 단계

1. 물리 호스트 CPU, 메모리, 저장공간, 가상화, 네트워크와 Hyper-V 상태를 확인한다. Windows Server 2022 VM의 중첩 Hyper-V 지원, 실제 사용 가능한 자원과 허용 사설망을 기록한다.
2. 물리 호스트에 컴퓨트 노드 VM을 만들고 중첩 가상화를 허용한 뒤 내부에 Hyper-V를 설치한다. 컴퓨트 노드에서 Rocky Linux 테스트 VM 한 대를 수동 생성·부팅한다.
3. 컴퓨트 노드에서 VM 생성·조회·상태 변경·삭제를 PowerShell로 재현한다. 반복 실행, 실패 처리, 재시도와 복구를 검증한다.
4. 컴퓨트 노드 IIS 수신부를 시험 설치한다. 같은 물리 PC의 관리포털이 지정된 컴퓨트 노드 IP로 HTTPS cURL 요청을 보내고 IIS가 고정 PowerShell 절차를 호출한다. API는 등록한 사설망 고정 출발지 IP만 허용한다. 사설 CA 인증서를 PHP가 신뢰하고 CA 개인키는 호스트 밖에 오프라인 보관한다. IIS 기술은 공식 지원성·호스트 확인 후 사용자에게 선택지를 제시한다.
5. Windows Server 2022 AD VM과 Windows Server 2022 VMM·SQL Server 통합 VM을 준비한다. VMM 2022·SQL Server 2022의 지원 업데이트와 사용 권한을 확인한 뒤 컴퓨트 노드를 VMM에 편입한다. IIS 수신부는 VMM VM으로 이전하고 공식 VMM PowerShell 명령으로 작업하도록 연결한다. 이전 뒤 작업 권한·대상 IP·완료 상태 계약을 다시 검증한다. 클러스터·DPM은 환경·라이선스가 확보된 범위만 진행한다.
6. VMM 편입 뒤 포털의 첫 회원 신청으로 컴퓨트 노드 안에 Rocky VM 한 대를 만들고 부팅·상태·사양을 대조한다. 이후 VM 전체 동작과 실패·복구를 검증한다.

## 완료 확인

- 단일 물리 호스트 안의 컴퓨트 노드에서 VM 생성·상태 변경·삭제의 실제 결과와 자동화 기록이 일치한다.
- VMM 설치·컴퓨트 노드 편입과 IIS 이전의 성공·실패 결과를 기록한다.
- 포털에서 시작된 작업을 추적하고 실패 후 복구를 재현할 수 있다.
- 확장 단계는 사용한 환경과 검증 범위를 명시한다.

## 이후 결정

테스트 VM 사양, 로그 세부 형식과 제품 업데이트·사용 권한은 단계별 착수 전에 확인한다. 첫 게스트 OS는 Rocky Linux 10 계열이다. 정확한 가상 스위치·허용 10대역 서브넷은 사용자가 지정한다. 포털→IIS→PowerShell 경로, HTTPS 강제, 사설 CA 발급·신뢰, CA 개인키의 호스트 밖 오프라인 보관, IIS 서버 인증서 1년·만료 30일 전 갱신, 등록한 사설망 고정 출발지 IP의 API 허용은 확정했다. 첫 회원 신청은 VMM 편입 뒤 진행한다. 실제 IP, IIS 실행 계정·상태 조회 세부와 중첩 네트워크 방식은 사용자 결정 게이트로 남긴다.
