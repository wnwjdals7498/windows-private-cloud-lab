작성: 2026-10-02 · 범위: 계획·인계 문서 · 실제 코드/실호스트 구현 전

## 범위의 해석

- **추가:** 새로 제공할 관찰 가능한 기능·상태·검증·운영 행동.
- **수정:** 이미 있는 계약·행동을 어떤 의미로 바꾸는지. 기준선에 구현이 없으면 변경 전제를 함께 명시한다.
- **삭제:** 폐기할 실행 경로·권한·상태·의존성. 구현이 없으면 삭제 없음이라고 적는다. 코드 삭제가 고객 데이터 삭제 허용을 뜻하지 않는다.
- **input/output:** 값의 이름·뜻·원천·생산자/소비자·제약·실패 표현을 기술한다. 실제 IP·경로·사양·예제 ID·샘플 JSON 값으로 대신하지 않는다.
- 카드의 내부 의미 이름은 외부 JSON 필드를 추가하라는 지시가 아니다. 외부 wire 이름·필수성·버전은 SC01과 기존 Cloud strict 계약을 따르고, 새 필드는 소비자와 함께 버전을 정한다.
- **goal:** 시험으로 판정할 수 있는 결과. **non-goal:** 이번 카드가 책임지지 않는 행동·주체·환경.

이번 상세계획은 기존 설계·기술 추천·사용자 결정 게이트를 구체화한다. .NET/IIS 기술, 실제 네트워크, MSSQL 조회 대상 등 미정 선택을 승인된 사실로 바꾸지 않는다. 각 카드의 `추적 작업`은 주 책임이며, 다른 카드에서 같은 기능을 참조하는 것은 의존성·통합 시험을 뜻한다.

## 준비도와 완료

| 판정 | 의미 | 다음 작업이 사용할 수 있는 것 |
| --- | --- | --- |
| 계약 검토 완료 | 입출력·오류·소유권·전이가 합의되고 기준선이 고정됨 | 독립적인 consumer/provider 개발 기준 |
| 코드 검증 완료 | 구현이 단위·계약·필요한 로컬 통합 시험을 통과 | 승인된 해당 환경에서 배포 후보 |
| 실호스트 검증 완료 | 실제 IIS/DB/제품/VM/데이터로 기대 동작 확인 | 원래 P 단계의 선행 완료 증거 |
| 공동 인수 완료 | Cloud까지 실제 경로·권한·상태·SSH·복구 대조 | 해당 공동 기능 완료 |

문서·fake·모의 fixture가 통과한 상태를 코드 검증 완료 또는 실호스트 완료로 올리지 않는다. 부분 준비가 끝난 카드는 완료한 하위 행동과 미검증 항목을 남긴다. 계획의 전체 순서와 실제 변이 작업은 유지하고, host 없이 가능한 독립 코드 개발만 앞당긴다.
