# 병렬 구현의 공유 계약

아래는 **기준선으로 확정할 의미의 목록**이다. 타입/메서드 이름만 맞는 상태를 계약 완료라고 하지 않는다. 현재 값·제품 선택이 미정인 항목은 관련 게이트에서 고정한다. [기존 계약](../contracts.md)이 상세 의미의 원천이다.

## 계약별 책임과 인계

| ID | 의미·생산자 → 소비자 | 필수 의미 | 정합성·변경 소유자 |
| --- | --- | --- | --- |
| SC01 | 식별·명령·결과 / F01 → 전 카드 | Cloud 요청/작업/VM, Windows 논리 작업/VM, 실제 제품 ID, attempt·멱등 키·mode·version·오류의 구별 | F01 책임자가 제안, 주 에이전트가 소비자와 통합. 타 담당자는 독자 alias 추가 금지 |
| SC02 | 환경·catalog·실행 계획 / F02·F04·F05·F07 → 실행/운영 | 승인 환경·제품·역할·profile/image/network version, 값의 원천·미정/실측, 경로·신원 참조 | F02가 구성 의미 소유. 실제 환경·이미지 원천은 각 담당 검증 |

소유자가 여럿 표시된 계약은 lifecycle의 생산자 역할을 나눈 것이다. 한 시점의 변경 작성자는 주 에이전트가 한 명으로 지정하고 나머지는 소비자 검토를 맡는다. 역할 구분을 같은 공유 정의의 동시 편집 허용으로 해석하지 않는다.

## 병렬 개발 전에 고정할 것

각 공유 계약의 의미·필수/선택·단위·null/미관측·오류·전이·version 호환 규칙, producer/consumer, 원자성, fixture 판정 규칙을 먼저 합의한다. G04/G06이 아직 미정이면 독립적인 의미·검증 설계까지만 기준선으로 두고 특정 런타임/DB 구현을 승인됐다고 간주하지 않는다.

기준선에는 계약 revision, 관련 schema/fixture revision, 소비자 목록, 미정 게이트, 실제 검증 범위를 기록한다. 브랜치 이름이나 파일 생성 여부가 기준선을 뜻하지 않는다. consumer는 계약 mock을 독립 구현할 수 있지만 provider의 실패·부재·지연 의미를 생략해서는 안 된다.

## 통합 시 반드시 대조할 불변식

1. 같은 서비스 신원·환경·멱등 키와 같은 본문은 같은 접수에 연결된다. 다른 본문은 충돌이다.
2. 영속 접수 전 성공 접수 응답을 반환하지 않는다. 외부 실행을 DB 재시도 transaction 안에 넣지 않는다.
3. 접수의 논리 VM ID는 실제 VM 존재 증거가 아니다. 실제 ID는 관측 후 연결한다.
4. lease 만료·프로세스 timeout은 외부 작업 종료를 보장하지 않는다. 불명확 결과는 재조회하고 무조건 재생성하지 않는다.
5. 실제 VM 상태·게스트 준비·작업 완료·통지 전달·조회 신선도는 별도 의미다.
6. 현재 Cloud strict simulated 계약을 real·새 필드·새 상태로 조용히 바꾸지 않는다. 새 버전·소비자 검증을 함께 적용한다.
7. 완료 결과·audit·outbox의 원자성을 유지하고 HTTP 전송은 commit 후 수행한다.
8. 진단 로그 회수로 활성 원장·미전달 이벤트·멱등 tombstone·복구 자산을 지우지 않는다.
9. 고객 소유권은 Cloud, Windows는 서비스 신원·허용 대상·동작을 검증한다. 별도 회원 DB를 만들지 않는다.
10. VMM 내부 DB 쓰기, 관리 중 VM의 무단 Hyper-V 우회 변경, 동시에 두 모드 실행을 허용하지 않는다.

## 계약 변경 요청

담당자는 바꿀 의미·필요 이유·현재 소비자 영향·호환 가능 여부·DB/실행 중 작업 영향·검증·원복을 주 에이전트에게 전달한다. 주 에이전트는 affected consumer와 한 번에 정리하고 새 기준선으로 재배정한다. 소비자 각자가 호환 shim을 추가해 뜻이 다른 같은 필드를 유지하지 않는다.

공유 DTO/schema·오류/enum·공통 port·DI 조립·도구 버전·DB migration·통합 fixture·배포 manifest·AGENTS/인덱스는 통합 책임자의 변경 경계다. 기능 담당자는 요구와 검증 결과를 전달하고 임의로 공통 경계를 넓히지 않는다.

## 데이터·실행 배타성

테스트마다 환경·작업·자원 식별 범위를 분리한다. 동일 VM/주소/디스크/DB schema/인증서 binding을 둘 이상의 에이전트가 변경하지 않는다. 외부 자원 표식은 설정 이름 prefix 하나보다 명시적 환경/요청 binding을 기준으로 한다.

PMT의 start/delegate/lock은 작업 문서 점유·저장소 통합 통제용이며 런타임 VM lease를 대신하지 않는다. PMT 기록·원격 동기화·통합 결과는 주 에이전트가 관리한다. 서브에이전트는 자기 기능의 증거와 계약 변경 요청을 반환한다.
